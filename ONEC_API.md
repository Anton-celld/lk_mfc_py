# Обмен ЛК МФЦ ↔ 1С: HTTP-сервис

Документ для разработчиков 1С. ЛК МФЦ (личный кабинет студента и кабинет сотрудника МФЦ) — отдельный сервис на Python.
Источник правды о людях, программах, приказах, учётных записях и статусах заказов — **1С**. ЛК хранит у себя только
заказы и их ход, отзывы, настройки МФЦ и журнал.

ЛК ходит в 1С сам (1С никуда не обращается). Нужен один **HTTP-сервис 1С** с методами ниже.

- Базовый адрес: `config.json → onec.base_url`, например `https://1c.timacad.ru/univer/hs/mfc/`.
- Авторизация сервиса: Basic (служебная учётка) — `onec.user`, `onec.password`.
- Формат: JSON в UTF-8, даты — `ГГГГ-ММ-ДД`, дата и время — ISO 8601 (`2026-10-14T11:20:00`).
- Пути методов и названия статусов можно поменять в `config.json → onec.paths` и `onec.status_map` — переделывать 1С под ЛК не нужно.
- Работающий образец сервиса — имитатор `lk/mock1c.py` (по нему ЛК проверен автотестами).

Ошибки: `4xx` + `{"error": "текст"}` — запрос неверный (ЛК покажет ошибку или пометит заказ «ошибка 1С»);
`5xx`, таймаут — 1С недоступна (заказ останется в очереди и уйдёт при следующей синхронизации, раз в `onec.sync_every_sec`).

## 1. Вход: учётные записи генерирует 1С

ЛК поддерживает три способа — включаются в `config.json → auth.providers` (можно несколько через запятую).
Какой выбрать — решают 1С и ИТ; рекомендуемый — **onec_check**.

### onec_check — пароль проверяет 1С (рекомендуется)
`POST auth/check`
```json
{"login": "st100001", "password": "…"}
```
Ответ — пользователь найден:
```json
{"ok": true, "person": "100001", "role": "student", "name": "Иванов Иван Иванович"}
```
Не найден или пароль неверный: `{"ok": false}`.

`person` — код физлица (или другой постоянный ID), им ЛК потом запрашивает данные.
`role`: `student` — ЛК студента, `staff` — сотрудник МФЦ, `admin` — сотрудник с правом менять настройки МФЦ.

### onec_import — ЛК забирает сгенерированные учётки
`GET accounts?since=2026-10-01T00:00:00` (без `since` — все). ЛК вызывает раз в `auth.import_every_min` минут.
```json
{"accounts": [
  {"login": "st100001", "password_hash": "pbkdf2_sha256$260000$соль$хэш_base64", "person": "100001",
   "role": "student", "name": "Иванов Иван Иванович", "active": true, "updated": "2026-10-01T09:00:00"}
]}
```
Пароль передаётся **только хэшем**. Форматы:
- `pbkdf2_sha256$итерации$соль$хэш` — PBKDF2-HMAC-SHA256, хэш в base64 (как в Django);
- `sha256$соль$хэш` — SHA-256 от `соль + пароль`, хэш в hex (если в 1С проще посчитать так).

`active: false` — учётка отключена (отчислен, уволен).

### onec_token — одноразовая ссылка входа
1С формирует ссылку `https://адрес-ЛК/enter?t=ТОКЕН` (например, в своём личном кабинете или в письме).
ЛК проверяет токен: `POST auth/token` `{"token": "…"}` → ответ как у `auth/check`. Токен должен быть одноразовым и короткоживущим.

## 2. Данные студента

### Человек и его программы обучения
`GET persons/{person}`
```json
{"id": "100001", "fio": "Иванов Иван Иванович", "fio_dat": "Иванову Ивану Ивановичу",
 "birth": "2004-03-14", "gender": "m", "citizenship": "Россия", "email": "ivanov@example.ru", "phone": "+7 900 000-00-01",
 "programs": [
   {"id": "p1", "book": "231045", "level": "bak", "code": "38.03.01", "name": "Экономика",
    "profile": "Экономика предприятий и организаций АПК", "form": "очной", "course": 3,
    "basis": "бюджетной основе", "group": "ЭК-301", "inst": "Институт экономики и управления АПК",
    "start": "2024-09-01", "end": "2028-08-31", "enroll": {"n": "СК-1234", "date": "2024-08-03"},
    "calls": [
      {"id": "2027-1", "reason": "Промежуточная аттестация (зимняя сессия)", "from": "2027-01-11", "to": "2027-01-31"},
      {"id": "2027-2", "reason": "Промежуточная аттестация (летняя сессия)", "from": "2027-06-07", "to": "2027-06-27"}]}
 ]}
```
- `fio_rod` — ФИО в родительном падеже для шапки заявления («от студента … Иванова Ивана Ивановича»). Необязательно:
  если не передать, ЛК склоняет сам по правилам русских ФИО (`lk/names.py`), иностранные ФИО оставляет как есть.
- `fio_dat` — ФИО в дательном падеже (для справки «Дана Иванову Ивану Ивановичу»). Если не передать, будет именительный.
- `gender`: `m` / `f` (он/она в справке). Если нет — определяется по отчеству.
- `level`: `spo` — СПО, `bak` — бакалавриат, `spec` — специалитет, `mag` — магистратура, `asp` — аспирантура.
  Показывается в шапке ЛК («Специалитет, 3 курс»); от уровня зависят доступные услуги (перечень 2026–2027), подписант
  (бак/спец/маг — один, аспирантура — другой, СПО — третий) ; справка-вызов — только бакалавриат, специалитет, магистратура (ст. 173 ТК).
- `citizenship` — гражданство. Не Россия → иностранный гражданин: свой перечень услуг, выписки только разрешённых видов
  в 2 экземплярах. Можно вместо этого прислать `"foreign": true/false`.
- `book` — номер зачётной книжки (студент видит его в переключателе программ). Программы ведутся раздельно:
  заказы, уведомления и счётчики по одной зачётке в другой не видны.
- `enroll` — приказ о зачислении (номер и дата) для справки о подтверждении обучения; `start`/`end` — даты начала и
  предполагаемого окончания обучения.
- `form` и `basis` — в том падеже, как печатаются: «на 3 курсе **очной** формы обучения на **бюджетной основе**».
- Несколько программ — несколько элементов `programs`; заказ оформляется по выбранной.
- `calls` — периоды из графика учебного процесса, на которые выдаётся справка-вызов: `id` (уникален в программе),
  `reason` — основание, как его видит студент в выпадающем списке, `from`/`to` — даты вызова. Студент выбирает основание,
  даты подставляются сами; прошедшие периоды не показываются. Если `calls` не передать, даты берутся из календарного
  учебного графика, который МФЦ загружает файлом .xlsx/.csv в кабинете сотрудника (по группе `group`, см. `lk/kug.py`);
  если группы нет и там — студент выбирает основание из списка МФЦ и вводит даты сам.

ЛК кэширует ответ на 10 минут и хранит последнюю копию на случай, если 1С недоступна.

### Приказы студента (для выписки из приказа)
`GET persons/{person}/orders?program=p1`
```json
{"orders": [{"n": "3105-ст", "date": "2026-07-03", "type": "О переводе на следующий курс", "title": "О переводе на 3 курс"}]}
```
`type` — вид приказа в 1С. Иностранным гражданам ЛК разрешает выписки только видов из `FOREIGN_EXTRACTS` (`lk/catalog.py`:
«О переводе на следующий курс», «О назначении академической стипендии», «О выпуске» и др.); без `type` сравнивается заголовок.
Нужны те же приказы, что студент видит в разделе «Приказы» ЛК.

## 3. Заказы из ЛК → 1С

### Новый заказ
`POST requests` — ЛК отправляет сразу после того, как студент нажал «Отправить».
```json
{"lk_id": 17, "person": "100001", "program": "p1", "service": "study",
 "title": "Справка о подтверждении обучения (гербовая)", "created": "2026-10-14T11:20:00",
 "contacts": {"email": "ivanov@example.ru", "phone": "+7 900 000-00-01"},
 "kind": "gerb", "qty": 2,
 "org": {"inn": "7700000016", "kpp": "770001001", "ogrn": "…", "name": "ООО «Агрохолдинг Пример»",
         "full": "Общество с ограниченной ответственностью «Агрохолдинг Пример»", "address": "г. Москва, …"}}
```
Ответ:
```json
{"id": "5001", "number": "МФЦ-5001", "status": "reg"}
```
`id` — идентификатор заявки в 1С (по нему ЛК потом спрашивает статус), `number` — номер, который видит студент.

Поля по услугам (`service`):

| service | что приходит |
|---|---|
| `study` — справка о подтверждении обучения | `kind`: `ecp` (с ЭЦП), `gerb` (гербовая), `umu` (по месту требования, с печатью УМУ); `qty` — для бумажных; `org` — только у `gerb` (из ЕГРЮЛ по ИНН), у `ecp` и `umu` — `place: "по месту требования"`; для `ecp` — `signer` и `print_html` |
| `call` — справка-вызов | `reason` (основание), `call` (`id` периода из `calls`), `period: {from, to}`, `org` (из ЕГРЮЛ по ИНН, обязательно), `qty` всегда 1, `signer`, `call_article` (173 — вызов только у бакалавриата, специалитета и магистратуры), `call_purpose` (формулировка по ТК: «прохождения промежуточной аттестации»…), `print_html` — справка по форме приказа № 1368, которую студент проверил. Повторно по тому же периоду графика (или по тому же основанию на пересекающиеся даты) ЛК не принимает — кроме отменённых и отклонённых |
| `income` — справка о стипендии и иных доходах | `period: {from: "2026-01", to: "2026-09"}` (месяцы; `to` — не позже прошлого месяца, текущий — только за `income_days` дней до конца месяца, по умолчанию 4), `qty` |
| `income2` — справка о стипендии и иных доходах (по форме № 2) | как `income` |
| `extract` — выписка из приказа | `prikaz: {n, date, type, title}`, `qty`; у иностранных граждан `foreign: 1` и `qty: 2` (второй экземпляр — в Управление международного сотрудничества) |
| `app0`…`app27`, `x…` — заявления | `fields` — что заполнил студент (ключи — параметры из макета 1С: `Причина`, `ДатаНачала`…), `files: [{name, content_base64}]` — PDF (первый — подписанное заявление), `print_html` — заполненный бланк |

Если в выпадашке выбраны «иные обстоятельства» (`иным обстоятельствам` / `иными обстоятельствами`), рядом в `fields` приходит `<ключ>_иное` — что вписал студент (например, `Причина_иное`); в `print_html` они уже подставлены в скобках. В заявлении на перевод `НовыйФакультет`, `НоваяСпециальность` («код название»), `НоваяСпециализация` — значения из справочника направлений по КЦП 2026/27.

- **Справка с ЭЦП**: студент видел печатную форму (`print_html`) и подтвердил её, заказ приходит со статусом `sign`
  и с подписантом `signer: {level, fio, fio_full, pos}` — подписант группы уровней образования, назначенный в настройках МФЦ
  (по умолчанию С.А. Захарова). 1С сразу передаёт её на подпись.
- **Лимит**: бумажных экземпляров `qty` — не больше лимита из настроек МФЦ (по ТЗ — 3); ЛК больше не пропустит.
- **Организация** — только из ЕГРЮЛ по ИНН (проверка контрольных цифр, ликвидированные не принимаются); студент её название не вводит.

### Изменение заказа
`PUT requests/{id}` — тело как у создания. Студент может изменить заказ в статусах `reg` и `need`
(«Требуется действие»; после исправления 1С должна вернуть заказ в работу — `work`).

### Отмена
`POST requests/{id}/cancel` — студент отменяет только заказ в статусе `reg`.

### Автоотклонение («Требуется действие» без ответа)
`POST requests/{id}/reject` — тело `{"reason": "Заказ отклонён автоматически: …", "auto": true}`.
Если заказ в статусе `need` и студент не исправил его за `need_days` рабочих дней (по умолчанию 2; день, когда поставили
`need`, не считается; праздники — из настроек МФЦ), ЛК сам переводит заказ в «Отклонено», уведомляет студента и
отправляет этот вызов. 1С должна перевести заявку в «Отклонено» с этим комментарием. Пример: `need` поставили в среду
14.10 → исправить можно до пятницы 16.10 включительно → в понедельник 19.10 заказ отклоняется.
Срок меняется в кабинете сотрудника: Настройки → Сроки и лимиты (0 — не отклонять).

## 4. Статусы 1С → ЛК

`GET requests?since=2026-10-14T11:00:00` — ЛК опрашивает раз в `onec.sync_every_sec` секунд; `since` — наибольший `updated` из прошлого ответа.
```json
{"requests": [
  {"id": "5001", "number": "МФЦ-5001", "status": "ready", "comment": "", "updated": "2026-10-14T11:40:12.123456"}
]}
```
Статусы ЛК:

| код | что видит студент |
|---|---|
| `reg` | Зарегистрировано |
| `work` | Передано исполнителю |
| `sign` | Технический статус 1С. Для бумажных документов — передано на подпись; для справки с ЭЦП — передано на электронную подпись; для обычных заявлений — передано в дирекцию |
| `need` | Требуется действие — `comment` обязателен, студент его видит и исправляет заказ; после исправления заказ возвращается в прежний статус |
| `ready` | Выполнено (можно забирать в МФЦ) |
| `done` | Выдано (забрано) |
| `signed` | Подписано (справка с ЭЦП — готовый скан, можно скачать) |
| `rej` | Отклонено — `comment` с причиной |
| `cancel` | Отменено (студентом, пока заказ «Зарегистрировано») |

Маршруты (в заказе приходит `flow`):

| `flow` | что | статусы по порядку |
|---|---|---|
| `paper` | справка об обучении (гербовая, по месту требования), справка-вызов, выписка из приказа | `reg` → `sign` → `ready` → `done` |
| `long` | справка о стипендии и иных доходах, она же по форме № 2, заявление на справку о периоде обучения | `reg` → `work` → `sign` → `ready` → `done` |
| `app` | остальные заявления | `reg` → `work` (конечный). На стороне ЛК статусы `work` и `sign` для этого потока отображаются как «Передано в дирекцию» и считаются конечными |
| `ecp` | справка об обучении с ЭЦП | `sign` → `signed` |

Можно присылать и названия статусов 1С («Передано исполнителю», «Выдано», «Отказано» и т. п.) — типовые ЛК понимает сам,
остальные задаются в `onec.status_map`. При смене статуса студент получает уведомление в ЛК.

### Подписанная справка с ЭЦП
`GET requests/{id}/document` → подписанный файл PDF (`Content-Type: application/pdf`) с визуальной отметкой электронной подписи. Для электронного документа используется усиленная квалифицированная электронная подпись; бумажная печать не требуется. Визуальную отметку ЭП на PDF формирует 1С при подписании.
`GET requests/{id}/signature` → отсоединённая подпись к этому PDF (`Content-Type: application/octet-stream`, обычно файл `.sig`). Оба метода доступны только после статуса `signed`; ЛК отдаёт оба файла студенту в карточке заявки. Подпись должна быть именно от 1С и соответствовать возвращаемому PDF. В демо-режиме `.sig` — заглушка для проверки интерфейса, она не является действительной электронной подписью.

## 5. Необязательно

`GET signers` → `{"vo": {"fio": "С.А. Захарова", "fio_full": "Захарова Светлана Алексеевна", "pos": "…"}, "asp": {…}, "spo": {…}}` —
если подписантов удобнее вести в 1С. Пока подписанты задаются в кабинете сотрудника МФЦ.

## Проверка сервиса 1С
1. Запустить ЛК против настоящего сервиса: `onec.base_url` → адрес 1С, `python run.py`.
2. Открыть `…/health` — `onec: true`, `queue` — сколько заказов ждут отправки.
3. Войти студентом, оформить справку; в кабинете сотрудника у заказа должен появиться номер из 1С.
