# Услуги МФЦ (Бета) — студенческий Python-сервис

Это **Python/aiohttp**, не PHP-модуль. Сборка подготовлена на основе `lk_mfc_status_labels.zip` и содержит **только студенческий интерфейс и API**. Кабинет сотрудников, демонстрационные кнопки и отдельный вход по логину/паролю отключены в `portal_run.py`. Старый раздел «Заказ справок, подача заявлений» в Yii2 не меняется.

## Реализовано в Python

- Каталог справок и заявлений с учётом программы обучения, документы и ЭЦП, история, уведомления, оценка.
- Начальный статус обычных заявок `reg` = **«Зарегистрировано»**; справок с ЭЦП `sign` = **«Передано на подпись»**.
- Последующая синхронизация через HTTP-клиент 1С (`lk/onec.py`) или новый конфигурируемый SOAP-адаптер (`lk/onec_soap.py`). Названия/коды в `onec.status_map`. Полное описание нового режима: `SOAP_INTEGRATION.md`.
- Защищённый вход по одноразовому HMAC-SHA256 билету из портала; повторное использование отклоняется.
- API студента проверяет собственную сессию и авторство заявки. Роли сотрудников и маршруты симуляции не регистрируются.

## Важная граница ответственности

**Нельзя просто положить Python-файлы в Yii2/PHP и получить новый раздел.** Сборщик портала должен сделать *небольшую точку входа на стороне существующего портала* (технология портала — PHP): добавить пункт меню **«Услуги МФЦ (Бета)»**; для авторизованного студента сформировать короткоживущий билет; перенаправить на `/mfc-beta/portal-enter?ticket=...`; организовать reverse proxy `/mfc-beta/*` → `127.0.0.1:8091`. Пароль студента Python-сервис не получает.

SSO-идентификатор `sub` должен быть **реальным ID физлица/студента из 1С**, который понимает `persons/{id}`. Его нельзя подменять логином или ФИО. Прикладной код портала обязан брать ID из подтверждённой серверной сессии, а не из параметров запроса.

**Интеграция с реальной 1С не гарантируется этим архивом.** Исходный Python-МФЦ вызывает пользовательский HTTP-сервис (`persons/{id}`, `requests`, `requests/{id}/document` и т. д.). Портал Yii2 использует свои SOAP/методы `CreateInquiry`, `GetInquiries`, подписанные файлы. Добавлен SOAP-транспорт, однако для реального запуска сборщику нужно **сопоставить методы и структуры по фактическому WSDL** (`onec.soap.operations`) и проверить ответы. Новые заявки хранятся во временной очереди Python SQLite до подтверждённой отправки в 1С. Это **не** единая база существующих заявлений портала, пока адаптер не реализован. Нельзя направлять в продуктив без проверки дублей и идентификаторов.

## Протокол единого входа

Секрет 32+ случайных байта в UTF-8 — только в окружении сервера и на доверенной стороне портала (`MFC_PORTAL_SSO_SECRET`), не в клиентском JS/HTML и не в ZIP. Формат билета:

`base64url(UTF8(JSON)).base64url(HMAC_SHA256(secret, base64url(UTF8(JSON))))`

Пример JSON (значения должны браться только из серверной сессии):

```json
{"iss":"student-portal","aud":"mfc-beta","sub":"<ID_1C>","name":"<ФИО>","role":"student","iat":1234567890,"exp":1234567950,"nonce":"<случайная_строка_24+>"}
```

`exp` максимум +60 секунд, nonce уникальный, время источников синхронизировать. Для проверки формата билета и подписи см. **`lk/portal_sso.py`** (`sign_ticket` — пример подписанта **на Python для тестов**; серверный портал должен формировать идентичную подпись своим кодом). HTTPS обязателен; ограничьте доступ напрямую к порту 8091; не записывайте query ticket в access-логи веб-сервера, PHP, систем мониторинга. После входа Python выставляет HttpOnly, SameSite=Lax, Secure-сессионный cookie на путь `/mfc-beta/`.

## Установка на Linux (отдельно от работающего ЛК)

1. Создать резервную копию работающего портала и МФЦ. Распаковать архив, например в `/root/lk_mfc_py`.
2. Создать `/etc/lk_mfc_beta.env` с переменной `MFC_PORTAL_SSO_SECRET=<длинный_случайный_секрет>` (например генерировать через `python3 -c 'import secrets;print(secrets.token_urlsafe(48))'`). Права 600; не пересылать секрет.
3. В `portal_config.json` (копия `portal_config.example.json`) установить реальный HTTPS `public_url`, `base_path=/mfc-beta` и `onec.base_url`, логин, пути, при необходимости `onec.status_map`. Файл приватный, не отправлять в чат.
4. Установить: `sudo bash /root/lk_mfc_py/install_portal_beta.sh` — создаст отдельную службу `lk-mfc-beta` и каталог `/opt/lk_mfc_beta`.
5. В reverse proxy: **удалять префикс** `/mfc-beta/` перед отправкой в Python (`handle_path /mfc-beta/*` в Caddy, или эквивалент `proxy_pass http://127.0.0.1:8091/` в Nginx).
6. Добавить пункт меню и формирование SSO-билетов на стороне портала. Проверить `curl http://127.0.0.1:8091/health` (не содержит персональных данных).

В Caddy внутри нужного сайта (сборщик адаптирует к существующей конфигурации):

```caddy
redir /mfc-beta /mfc-beta/
handle_path /mfc-beta/* {
    reverse_proxy 127.0.0.1:8091
}
```

## Проверки перед выпуском

- Существующий пункт «Заказ справок, подача заявлений» остался работоспособным.
- Несуществующий/просроченный/повторно использованный SSO-билет отклоняется; сотрудники не могут войти.
- Студент видит только свои программы, заказы и документы (проверка с двумя тестовыми студентами).
- Обычная заявка после создания: «Зарегистрировано», ЭЦП: «Передано на подпись».
- Реальный `CreateInquiry` создаёт **одну** заявку, обновления реального `GetInquiries` отображаются правильно, PDF и подпись скачиваются.
- Заявление с отказом, потребностью уточнения, выдачей, отменой обрабатывается согласно правилам 1С.

## Ограничения

Пока не выполнено ручное сопоставление API 1С и SSO-механизма портала, архив — **Python-заготовка для интеграции/тестирования**, а не готовый промышленный релиз. Сам скрипт не изменяет файлы действующего Yii2-портала.
