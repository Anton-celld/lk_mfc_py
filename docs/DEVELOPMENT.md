# Разработка и проверки

## Рабочий процесс

Разрабатывайте изменения в отдельных ветках, открывайте Pull Request, проверяйте тесты и дифф перед объединением с `main`. Не совмещайте миграцию авторизации, изменение SOAP-контракта и изменение бизнес-правил заявлений в одном непроверяемом обновлении.

## Окружение

Для базового Python-окружения:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Для SOAP-режима дополнительно:

```bash
python -m pip install -r requirements-soap.txt
```

Примеры настроек: `.env.example`, `config.example.json`, `portal_config.example.json`. Никакие настоящие секреты в репозиторий не добавлять.

## Тесты

```bash
python -m pytest -q
```

При использовании Docker можно выполнить `make test`, который собирает тестовый образ.

Проверки без сети 1С не подтверждают корректность реальных SOAP-операций. Интеграционные испытания необходимо проводить в разрешённой внутренней сети с тестовой технической учётной записью.

## Контроль перед Pull Request

- Изменение не нарушает стартовые статусы: «Зарегистрировано» и «Передано на подпись».
- Существующий HTTP-транспорт 1С продолжает работать при `MFC_ONEC_TRANSPORT=http`.
- SOAP-методы подтверждены настоящим WSDL, либо чётко отмечены как не проверенные.
- Создание заявки после тайм-аута не повторяется автоматически без сверки.
- Проверки доступа выполняются сервером для всех маршрутов, включая документы.
- Нет токенов, паролей, персональных данных, ключей TLS и рабочих конфигураций в `git diff --cached`.
- В `CHANGELOG.md` и документации зафиксированы изменения, настройки и ограничения.
- Для изменений схемы данных описаны резервная копия, миграция и откат.

## Важные ограничения

Настоящий WSDL 1С доступен только внутри сети организации и защищён логином и паролем. `X-Service-Token` ещё не интегрирован в этот сервис. До завершения проверки доступа по выбранной зачётке продуктивное использование с персональными данными не допускается.
