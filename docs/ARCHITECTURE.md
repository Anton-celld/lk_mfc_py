# Архитектура `lk_mfc_py`

## Назначение

«Услуги МФЦ (Бета)» — отдельный Python/`aiohttp`-микросервис для студентских обращений, справок и статусов. Его интерфейс и API не заменяют автоматически существующий раздел портала.

## Компоненты

```text
Личный кабинет / браузер
          |
    Платформенный шлюз
          |
     lk_mfc_py (aiohttp)
        |       |
        |       +-- локальные сессии, очередь, метаданные
        |
    прикладной API OneC
       |             |
  HTTP-клиент     SOAP-адаптер
       \             /
           1С
```

Текущая схема входа является исключением из общей схемы шлюза: сервис обменивает короткоживущий билет BFF на собственную сессию. Схема `X-Service-Token` пока целевая, но не реализована, см. [AUTH.md](AUTH.md).

## Структура кода

- `portal_run.py`: запуск отдельного студенческого сервиса.
- `lk/web.py`: HTTP-маршруты и настройка приложения.
- `lk/auth.py`, `lk/portal_sso.py`: сессии и текущий билет входа.
- `lk/db.py`: локальное хранилище.
- `lk/orders.py`: действия с заявлениями и синхронизация.
- `lk/catalog.py`: каталог услуг.
- `lk/onec.py`: HTTP-операции к 1С и общий выбор транспорта.
- `lk/onec_soap.py`: SOAP-операции через `zeep`.
- `static/`, `templates/`: ресурсы интерфейса.
- `deploy/`, `docker-compose.yml`: развёртывание и регистрация в Consul.

## Два разных вида HTTP

1. Межсервисное HTTP-взаимодействие и маршрутизация через Gateway.
2. Опциональный HTTP-транспорт **к 1С**, выбираемый `MFC_ONEC_TRANSPORT=http`.

При `MFC_ONEC_TRANSPORT=soap` меняется только второй вид. Взаимодействие сервисов по HTTP остаётся.

## Интеграция 1С

`onec.transport` принимает `http` или `soap`, используя схожий прикладной API методов. SOAP-адаптер не выдумывает имена операций; `onec.soap.operations` необходимо заполнить по реальному WSDL и проверенным ответам. WSDL доступен во внутренней сети и требует отдельной технической аутентификации к 1С.

Без сетевого доступа, учётных данных и настоящего WSDL нельзя подтвердить совместимость операций создания, чтения статусов, PDF и отсоединённых подписей.

Не допускать слепых повторов создания обращения после неопределённого ответа: операция могла быть успешно выполнена в 1С. Требуются сверка и согласованная идемпотентность.

## Границы безопасности

Пользовательский токен платформы (будущий `X-Service-Token`) и техническая учётная запись SOAP не взаимозаменяемы. Проверка роли без ограничения данных по выбранной зачётке недостаточна.

Внедрение с реальными данными требует проверки модели доступа, файлов, SSO, логирования, хранения секретов и обработки ошибок. Подробнее — [AUTH.md](AUTH.md) и [SOAP_INTEGRATION.md](../SOAP_INTEGRATION.md).
