# Услуги МФЦ (Бета) · `lk_mfc_py`

Python-микросервис личного кабинета студента для подачи заявлений, заказа справок и отслеживания их статусов с интеграцией 1С. Проект разрабатывается как отдельный сервис: действующий раздел портала не заменяется автоматически.

> **Состояние:** интеграционный прототип. Не использовать с реальными персональными данными и продуктивной 1С до проверки авторизации, ограничения доступа по выбранной зачётной книжке, SOAP-контракта и операций выдачи документов.

## Что находится в репозитории

- Студенческий веб-интерфейс и API на Python / `aiohttp`.
- Каталог услуг, история обращений, файлы и статусы заявлений.
- Интеграция с 1С через выбираемый транспорт `MFC_ONEC_TRANSPORT=http|soap`.
- HTTP-клиент `lk/onec.py`; экспериментальный SOAP-адаптер `lk/onec_soap.py` на `zeep`.
- Вход из личного кабинета по краткоживущему одноразовому билету BFF; переход на `X-Service-Token` **ещё не реализован**.
- Docker Compose, регистрация сервиса в Consul и тесты.

Статус обычной новой заявки: **«Зарегистрировано»**; заявки с ЭЦП: **«Передано на подпись»**. Дальнейшие статусы должны поступать из 1С.

## Быстрый старт для разработчиков

Необходимы Docker и доступ к инфраструктуре платформы, если используется `docker-compose.yml` с внешней сетью `platform` и Consul.

1. Скопировать пример переменных: `cp .env.example .env`.
2. Задать обязательный `MFC_PORTAL_SSO_SECRET` и корректный `MFC_PUBLIC_URL`, настроить 1С и прочие параметры для своей **тестовой** среды.
3. При наличии платформенной сети: `docker compose up -d --build`.
4. Проверять состояние и журналы через `docker compose ps` и `docker compose logs -f`.

Без готового шлюза, настроенного SSO и работающей 1С это не является полнофункциональным стендом. Для альтернативного запуска через `portal_run.py` см. [инструкцию портальной интеграции](README_PORTAL_PYTHON.md). Локальный HTTP допускается только на отдельном стенде с соответствующей настройкой, не в рабочем окружении.

Тесты: `make test` (Docker) либо после установки зависимостей `python -m pytest -q`. Для SOAP-зависимостей: `python -m pip install -r requirements-soap.txt`.

## Конфигурация 1С

| Переменная | Назначение |
| --- | --- |
| `MFC_ONEC_TRANSPORT` | `http` либо `soap` |
| `MFC_ONEC_BASE_URL` | Адрес HTTP-сервиса 1С |
| `MFC_ONEC_WSDL` | Адрес защищённого WSDL (внутренняя сеть) |
| `MFC_ONEC_LOGIN` / `MFC_ONEC_PASSWORD` | Техническая учётная запись для 1С |
| `MFC_ONEC_TIMEOUT` | Тайм-аут обращения |
| `MFC_ONEC_CA_FILE` | Файл доверенного корпоративного CA, если требуется |

SOAP требует настройки фактических имён, параметров и ответов операций из доступного в университетской сети WSDL. Включение `soap` **не делает интеграцию автоматически совместимой с 1С**. HTTP между микросервисами и API Gateway остаётся отдельным механизмом и не отключается.

## Безопасность и состояние внедрения

Не коммитьте `.env`, `config.json`, `portal_config.json`, базы, токены, пароли, реальные WSDL с чувствительными адресами или документы студентов. Проверяйте staged-файлы перед каждым `git push`. Технические секреты хранятся в окружении сервера.

Сейчас требуется отдельно реализовать и протестировать приём `X-Service-Token` от Gateway, серверное ограничение доступа по выбранной зачётке и безопасную смену контекста. Для реальной 1С нужны интеграционные испытания внутри разрешённого сетевого сегмента.

Репозиторий приватный. Права на исходный код и условия распространения отдельно не определены; лицензия не заявлена.
